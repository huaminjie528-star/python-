## DeepSeek 接入

- 根据官方接口为 `api.deepseek.com` 使用 `max_tokens`，并显式关闭思考模式，先完成非思考模式的四工具循环兼容。
- 保持 OpenAI 请求参数不变，增加缺失 Key 的本地检查。
- 区分余额不足、频率限制、账户上限、认证失败与接口不存在，避免统一提示“检查 Key”。不把服务端原始响应或密钥放进错误提示。
- 模拟 DeepSeek 服务的多轮工具调用测试覆盖读取文件与结果回灌。
- 发现用户配置中 DeepSeek 模型搭配 OpenAI 地址，纠正服务地址后，实际 DeepSeek 基础对话返回“连接成功”。没有在此基础上宣称真实模型文件操作全部通过。

## 网络问题

- 为 DNS 解析失败、连接拒绝、证书错误、TLS 握手、超时及连接重置增加分类提示。
- 每次请求重新创建 urllib opener，使系统代理变动不必等待进程重启。
- 不自动重发超时请求，避免在服务端已经接受请求的情况下重复调用。
- 把“已连接模型，开始任务”改为“正在请求模型，等待服务端响应”，明确区分开始请求与连接成功。
- 检测时本机存在系统代理，公开 HTTPS 探测当时成功。旧版未记录 URLError 的具体原因，不能据此断定每次失败都由代理引起。
